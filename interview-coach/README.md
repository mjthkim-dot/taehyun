# 🎤 영어 면접 코파일럿 — IT 영업 직군

Smooth AI를 벤치마킹한 **실시간 영어 면접 비서** (완전 독립 프로젝트).
핵심은 두 가지: **실시간 음성 번역**(영어 발화 → 한국어 자막)과
**실시간 답변 추천**(질문 감지 → 바로 읽을 수 있는 영어 답변 + 한국어 번역).

- **STT(자막)**: 브라우저 Web Speech — 유일한 무료 '실시간 스트리밍' 인식
- **LLM(번역·답변)**: **Groq → Cerebras → Gemini → Ollama 4중 자동 전환** —
  실시간 퀄리티가 핵심이므로 70B급 클라우드를 앞순위로 유지하고, 회사망이
  api.groq.com을 막아도(403) Cerebras(오픈소스 70B·무료 1M토큰/일) →
  Gemini(구글 도메인·무료) → 로컬 Ollama 순으로 즉시 넘어가
  **하나만 살아있으면 번역·답변이 끊기지 않는다**

## 실행

```bash
# LLM 키는 하나만 있으면 된다 (앞순위가 막히면 자동으로 다음 공급자 사용)
export GROQ_API_KEY=gsk_...      # https://console.groq.com  (회사망에서 403이면 아래로)
export CEREBRAS_API_KEY=csk-...  # https://cloud.cerebras.ai  (오픈소스 70B, 무료 1M토큰/일)
export GEMINI_API_KEY=...        # https://aistudio.google.com/apikey  (무료·회사망 통과율 높음)
bash start.sh                    # 시작 배너에 공급자별 ✅/❌ 상태가 표시된다
# → http://localhost:3778/live.html       (🔴 실전 화상 면접 코파일럿)
# → http://localhost:3778/interview.html  (연습 모드)
```

> 오프라인 보험: `ollama pull qwen3:8b` — 클라우드가 전부 막혀도 로컬 모델로 동작
> (한국어 자연스러움이 소형 오픈소스 중 최상위, 16GB 맥북에서 여유).

의존성 0 — stdlib만 사용하는 단일 파일 Python 서버라 `pip install`이 필요 없다.
라이브 모드는 **맥 Chrome**을 권장한다 (BlackHole로 화자 분리까지 가능).
폰에서도 동작하며, 그때는 오디오 라우팅 없이 폰 마이크로 듣는 2대 구성이 된다.

## 📱 폰에서 쓰기

브라우저는 **HTTPS에서만 마이크를 허용**한다(`http://192.168.x.x`로 열면 라이브가
동작하지 않음). `start.sh`가 cloudflared가 있으면 HTTPS 터널을 자동 생성한다:

```bash
brew install cloudflared          # 최초 1회
brew install qrencode             # (선택) 터미널에 QR을 띄워 폰으로 바로 열기
bash start.sh
#  📱 폰에서 열기
#     ├ 🔴 라이브:  https://xxxx.trycloudflare.com/live.html
#     └ 🎧 연습:    https://xxxx.trycloudflare.com/interview.html
```

주소는 실행할 때마다 바뀌고, 맥에서 서버가 켜져 있어야 접속된다.
사파리/크롬에서 공유 → **홈 화면에 추가**하면 앱처럼 설치된다.

### 🔴 폰 라이브 모드 — 2대 구성 (오디오 설정 불필요)

폰에는 BlackHole 라우팅이 불가능하므로 구성이 다르다. **노트북에서 화상면접을
하고, 폰을 옆에 둬서 방 소리를 듣게 한다** — 오디오 라우팅 설정이 아예 필요 없다.

```
[노트북] Zoom/Meet 면접 진행 — 스피커로 소리 재생 (이어폰 X)
   ↓ 소리
[폰] live.html에서 ▶ — 면접관 말을 듣고 자막 + 한국어 번역 + 답변 카드
```

폰에서는 장치 선택 바와 BlackHole 안내가 자동으로 숨겨지고, 답변 카드가 하단
시트로 바뀌며(헤더 고정 + 내부 스크롤), 퀵 액션이 2×2로 배치된다.

| 기기 | 라이브 | 연습 |
|---|---|---|
| **Android Chrome** | ✅ 실시간 인식 동작 | ✅ |
| **iPhone Safari/Chrome** | ⚠️ WebKit은 실시간 인식이 불안정 — 안내 문구 표시 | ✅ 전부 동작 |
| **맥 Chrome** ⭐ | ✅ BlackHole로 화자 분리까지 (권장) | ✅ |

> 아이폰에서 라이브가 안 되면 연습 모드를 쓰거나, 실전은 맥 Chrome을 쓴다.
> 연습 모드는 iOS에서 audio/mp4로 녹음돼 서버가 자동 처리한다.

## 🔴 라이브 모드 — 화자 물리적 분리 (BlackHole)

두 **입력 장치**를 각각 캡처해서 화자를 100% 정확히 나눈다:

```
▶ 시작
 ├─ 상단 '상대(면접관)' 드롭다운 = BlackHole (루프백)
 │    └─ 화상회의 앱 오디오가 BlackHole로 들어와 면접관 목소리가 됨
 └─ 상단 '내 목소리' 드롭다운 = 실제 마이크

각 장치 → VAD(0.6초 침묵 시 문장 단위 컷) → /api/stt → Groq Whisper
 → 상대 발화: 자막 + 한국어 번역 + 질문 감지 시 답변 카드 자동 생성
 → 내 발화:   갈색 버블로 기록 (요약·맥락에 사용)
```

### macOS BlackHole 셋업 (1회)

1. `brew install blackhole-2ch` (또는 [공식 설치 파일](https://existential.audio/blackhole/))
2. **오디오 MIDI 설정** 앱 → `+` → **다중 출력 장치(Multi-Output Device)** 생성 →
   내 스피커/이어폰 + **BlackHole 2ch** 체크
3. 화상회의 앱(또는 시스템)의 **출력**을 그 다중 출력 장치로 지정
   → 면접관 소리가 내 귀(이어폰)와 BlackHole 양쪽으로 감
4. 앱 라이브 모드에서 **상대(면접관) = BlackHole**, **내 목소리 = 실제 마이크** 선택

- 앱이 **BlackHole 장치를 자동 감지**해 '상대' 입력에 기본 선택한다 (수동 변경 가능).
- **이어폰 OK · 네이티브 Zoom/Teams 앱 OK** — 탭 공유가 필요 없다.
- 상대 채널은 오디오 처리(에코 캔슬 등)를 꺼서 깨끗한 디지털 신호를 그대로 인식,
  내 마이크 채널만 에코 캔슬/노이즈 억제를 켠다.

### 화면 구성 (Smooth AI 벤치마킹)

| 요소 | 동작 |
|---|---|
| 상단 탭 `라이브 · 요약 · 번역` | 요약 = 전체 세션 한국어 정리, 번역 = 독립 KR↔EN 번역기 |
| `● 실시간 요약` 바 | 3발화마다 대화 핵심을 한국어 한 줄로 자동 갱신 |
| 채팅 버블 자막 | 상대/나 자동 구분 + 타임스탬프, 영어 아래 한국어 번역 스트리밍 |
| ✦ 답변 카드 | 질문 요지(한국어) → `전략` → `답변` 2개 (영어 볼드 + 한국어 번역 + 🔊). **📌 고정** 시 자동 감지가 카드를 덮어쓰지 않음 (읽는 중 보호) |
| 퀵 액션 | 👍 동의하기 · 👎 반박하기 · 💬 질문하기 · 💡 제안하기 — 의도별 문장 생성 |
| 하단 입력 | 한국어 문장/단어 → 즉시 영어 변환 (전용 출력줄 — 답변 생성을 방해하지 않음) |
| **📋 세션 리포트** | ⏹ 종료 시 자동: 잘한 점 · 표현 업그레이드 · 예상 꼬리 질문 · 연습 포인트 + 트랜스크립트 .txt 다운로드 |

안정성:
- **STT 자동 복구** — 인식 오류(429 한도 등) 시 지수 백오프로 재시도하며 상태를 화면에 상시 표시 (조용히 죽지 않음)
- **언어 자동 감지** — 한국어/영어 혼용 면접에서도 자막이 깨지지 않음 (Whisper 자동 감지)
- **로컬 전용 바인딩** — 기본 127.0.0.1 (LAN의 타인이 내 Groq 키를 쓰는 것 차단, 공유 필요 시 `HOST=0.0.0.0`)
- 연습 모드 STT도 Groq Whisper로 통일 (라이브와 동일한 인식 품질)

질문·표현 은행은 `backend/data/interview_bank.json`에서 직접 수정.

### 🎯 타겟 회사 맞춤 모드

연습 모드의 **"타겟 회사 설정"**에 채용공고(JD)를 붙여넣고 저장하면:

1. **그 회사 예상 질문 8개**가 자동 생성돼 질문 은행에 병합된다
   (카테고리 `🎯 타겟 회사` — 연습 출제, ⚡ 사전 생성, 라이브 캐시 매칭에 모두 포함)
2. **모든 답변 생성이 회사 맥락으로 조정**된다 — 라이브 답변 제안, 연습 모범답변,
   사전 답변셋 전부. 특히 "Why our company?" 류 질문의 답변 품질이 크게 달라진다.

JD를 바꾸면 다시 저장 + ⚡ 맞춤 답변셋 재생성을 하면 된다.

## ⚡ 실시간성 — 말이 끝나기 전에 답변을 준비한다

브라우저 음성인식은 말이 끝난 뒤에도 **1~2초 지나서야 문장을 확정(isFinal)**한다.
그 시간을 그냥 흘려보내지 않고, **중간 인식 결과가 질문 형태로 완성되고 350ms
멈추면 답변 생성을 미리 시작**한다(투기적 선생성).

- 확정된 문장이 미리 생성에 쓴 문장과 유사(≥0.8)하면 **그대로 채택** → 추가 대기 0
- 다르면 즉시 재생성 (카드에 `미리 생성` 배지가 떠 있다가 확정되면 사라짐)
- 📌 고정 중이거나 이미 같은 질문으로 생성했으면 건너뛴다 → **질문당 요청 1회 유지**

측정(모의 면접, 확정 지연 1.4초 가정): 말이 끝난 뒤 답변이 화면에 뜨기까지
**1.81초 → 0.57초 (69% 단축)**. 자막 번역은 2개 레인으로 병렬 처리해 면접관이
빠르게 이어 말해도 밀리지 않는다.

### ⌨️ 실전 조작 (마우스 없이)

| 키 | 동작 |
|---|---|
| `Space` | 답변 카드 고정/해제 — 읽는 동안 새 질문이 덮어쓰지 않게 |
| `Esc` | 카드 닫기 |
| `+` / `-` | 답변 글자 크기 (100 → 120 → 145%, 저장됨) — 카메라를 보면서 곁눈질로 읽기 위해 |

## 🔒 지어내기 방지 — 말할 수 없는 답변은 만들지 않는다

면접에서 없는 숫자를 말하면 되묻는 순간 무너진다. 그래서 답변 생성 시
**내 프로필·스토리에 실제로 적힌 수치만** 쓰도록 제약한다.

- KB에서 추출한 실제 수치 목록을 프롬프트에 명시하고, 그 밖의 숫자·회사명·기간은 금지
- `[대괄호]`로 비어 있는 항목은 숫자를 만들지 않고 **정성적 표현으로 우회**
  ("a major manufacturing account")
- 답변 카드 하단에 **📎 근거**(어떤 내 사례에서 나온 답변인지)와,
  수치가 비어 있으면 그 사실을 함께 표시 → 무엇을 채워야 할지 바로 알 수 있다

## 🔎 날리지베이스 검색 — 맥락에 맞는 답변의 핵심

라이브에서 감지된 **영어 질문**이 한국어로 쓴 내 스토리·프로필과 정확히 연결되도록
3단 구조로 검색한다 (⚡ 사전 생성 버튼을 누르면 인덱스가 함께 만들어짐):

1. **사전 인덱싱** — 스토리마다 LLM이 **영어 태그·예상 질문·요약**을 미리 생성하고
   (`kb_index.json`), 은행 질문마다 **패러프레이즈**(같은 질문의 다른 표현)를 만든다.
   라이브 매칭은 이 영어 인덱스와 비교하므로 한국어 KB ↔ 영어 질문의 언어 장벽이 없고,
   "Describe a challenging situation…"처럼 어휘가 달라도 ⚡ 캐시가 히트한다
2. **의미(임베딩) 검색** — `ollama pull bge-m3`(~1GB, 선택)를 설치하면 질문을 로컬에서
   임베딩(~50ms)해 키워드 + 코사인 유사도 하이브리드로 스토리를 고른다.
   미설치면 키워드 검색으로 자동 폴백 (인덱스만으로도 효과 대부분 확보)
3. **세션 맥락** — 이미 말한 스토리는 기록해 **같은 사례를 반복 제안하지 않고**,
   "Why?" / "Can you give an example?" 같은 짧은 꼬리 질문은 **직전 질문에 연결**해
   같은 스토리의 다음 단계(결과·숫자·배운 점)로 이어간다. ▶ 시작/🗑 초기화 때 리셋

## ⚡ 맞춤 답변셋 사전 생성 (답변 0초 표시)

연습 모드(`/interview.html`)의 **⚡ 맞춤 답변셋 생성** 버튼을 누르면 내 프로필+스토리를
바탕으로 질문 은행 27개 전체의 답변을 미리 생성해 `backend/data/my_answers.json`에
저장한다 (Groq 기준 약 1분, 문항마다 저장되므로 중간에 끊겨도 진행분 유지).

라이브 모드에서 감지된 질문이 은행 질문과 매칭되면(키워드 겹침) **생성 과정 없이
저장된 맞춤 답변을 즉시(⚡ 표시) 띄운다** — 빈출 질문에 대한 체감 지연 0초.
매칭되지 않는 새로운 질문만 실시간 생성으로 넘어가며, 이때도 프롬프트가
**답변 문장을 가장 먼저 스트리밍**하도록 설계돼 첫 단어까지 1초 이내(Groq).
스토리를 수정했으면 버튼을 다시 눌러 재생성하면 된다.

## 음성 인식(STT) 엔진 — 실시간이 우선이면 '브라우저'

**중요**: 실시간 자막·번역이 필요하면 **브라우저(Web Speech) 엔진**을 써야 한다.
Whisper(로컬/Groq)는 정확하지만 **문장이 끝나야 인식하는 배치 방식**이라 몇 초 지연된다.

| 엔진 | 실시간성 | 비용/한도 | 화자 | 시스템 입력 |
|---|---|---|---|---|
| **브라우저(Web Speech)** ⭐기본 | ✅ **실시간**(말하는 대로) | 무료·무제한 | 면접관 실시간 + **내 목소리 별도 캡처** | **BlackHole로 설정 필요** |
| 로컬 Whisper | ❌ 배치(문장 단위 지연) | 무료·무제한·비공개 | 면접관+나 | 장치 드롭다운으로 선택 |
| Groq Whisper | ❌ 배치 | 무료 티어 RPM 한도 | 면접관+나 | 장치 드롭다운 |

### 브라우저(실시간) 엔진 셋업 — 핵심

Web Speech는 입력 장치를 지정할 수 없어 **시스템 기본 입력**만 듣는다. 따라서
면접관 소리를 들으려면 **시스템 입력을 BlackHole로** 바꿔야 한다:

```
시스템 설정 → 사운드 → 입력 → BlackHole 2ch 선택
(화상회의 앱 출력은 스피커+BlackHole 다중출력장치로 → 소리가 BlackHole로 흘러 인식됨)
```

시작 후 6초간 소리가 안 들리면 화면 상단에 이 안내가 자동으로 뜬다. 면접관 영어가
**말하는 대로 실시간 자막 → 문장 완료 시 한국어 번역 → 질문이면 답변 카드**로 이어진다.

> 최고 인식 정확도가 필요하고 약간의 지연을 감수할 수 있으면 헤더에서 'Whisper'
> 엔진으로 바꾼다 (로컬 설치 시 `pip install faster-whisper`).

**화자 분리는 이 모드에서도 유지된다.** Web Speech가 시스템 입력(BlackHole=면접관)을
실시간으로 받는 동안, **내 목소리는 마이크 장치를 따로 열어 Whisper로 받는다**
(내 발화는 실시간일 필요가 없고 맥락·세션 리포트에만 쓰이므로 배치로 충분).
서버에 STT 백엔드가 없거나 `대상: 상대만(절약)`이면 자동으로 생략된다.

### 🆓 로컬 Whisper 켜기 (권장)

```bash
pip3 install faster-whisper      # 최초 1회 (첫 실행 시 모델 자동 다운로드 ~140MB)
bash start.sh                    # "🆓 로컬 STT 활성" 확인
```

설치돼 있으면 서버가 **자동으로 로컬 인식을 사용**한다 (오디오가 클라우드로 안 나감,
요청 한도 없음, BlackHole 장치 선택 방식 그대로 = 화자 분리 유지). 라이브 페이지가
`/health`로 로컬 STT를 감지해 엔진을 '로컬 Whisper'로 자동 전환하고 요청 간격도 최소화한다.
미설치면 Groq Whisper로 자동 폴백된다.
- 모델 크기 조절: `STT_LOCAL_MODEL=small`(더 정확·느림) / `tiny`(빠름) / `base`(기본)
- 끄기: `STT_LOCAL=0`
- Apple Silicon에서 더 빠르게: `pip install mlx-whisper` 계열도 검토 가능(선택)

**브라우저 엔진**은 입력 장치를 지정할 수 없어 **시스템 기본 입력**만 듣는다. 따라서
**시스템 입력을 BlackHole로 설정**하면 면접관 발화가 무료·무제한으로 인식된다
(내 목소리는 위 설명대로 마이크 장치에서 따로 캡처되므로 화자 분리는 유지된다).

```
시스템 설정 → 사운드 → 입력 → BlackHole 2ch 선택   (브라우저 엔진용)
Zoom/Teams 마이크는 앱에서 실제 마이크로 따로 지정 (면접관이 내 목소리를 듣는 용)
```

번역·답변은 두 엔진 모두 LLM 자동 전환 체인(Groq → Cerebras → Gemini → Ollama)을 쓴다 —
질문당 몇 번뿐이라 무료 한도로 충분하다. **면접관 인식을 브라우저로 돌리면 STT 한도
문제가 사실상 사라진다** (내 목소리만 가끔 Whisper로 나감).

## Groq Whisper 엔진의 요청 한도(RPM) 대응

무료 티어는 분당 요청 수(RPM) 한도가 있어, 말이 계속 이어지면 STT 요청이 한도를
넘어 인식이 멈출 수 있다. 이를 자동으로 회피한다:

- **전역 요청 스케줄러** — STT 요청 간 최소 간격(기본 3.5초)을 강제해 RPM을 한도
  아래로 유지. 세그먼트는 큐에 쌓였다가 순차 전송된다.
- **상대(면접관) 우선** — 큐가 밀리면 '내 목소리' 세그먼트부터 버리고, 상대 발화는
  일시 실패(429) 시 한 번 재시도 → **질문 인식은 최대한 안 놓친다**.
- **429 적응형** — 한도에 걸리면 요청 간격을 자동으로 벌리고(최대 9초), 성공하면
  서서히 회복. 화면 우측 상단에 현재 원인/간격이 표시된다.
- **절약 모드** — 헤더의 `인식: 상대만(절약)`을 고르면 내 목소리 STT를 생략해
  요청 수를 절반으로 줄인다 (답변 추천에는 상대 발화만 필요하므로 실전에 무방).
- **세그먼트 길이** — 0.9초 침묵에서 문장 단위로 잘라(최대 14초) 요청 수를 줄인다.

여전히 자주 걸리면: 헤더에서 `인식: 상대만` + `민감도 낮음`으로 두면 가장 적게 나간다.

## VAD (음성 구간 감지) 튜닝

라이브 모드 상단의 **민감도 높음/보통/낮음** 셀렉터로 조절한다.
내부적으로는 고정 임계값이 아니라 **적응형 노이즈 플로어**(조용한 구간의 소음
레벨을 학습해 그 배수를 임계값으로 사용)라서 환경 소음에 자동 적응하고,
문장 컷은 0.6초 침묵 기준(최소 발화 0.3초, 최대 세그먼트 10초)이다.
- 상대 목소리가 잘 안 잡히면 → 민감도 높음
- 소음이 자막으로 자꾸 올라오면 → 민감도 낮음

## API

| 엔드포인트 | 동작 |
|---|---|
| `POST /api/stt?lang=en` (body: 오디오 바이트) | Groq Whisper 음성 인식 → `{text}` |
| `POST /api/live/suggest` `{question, cefr, context, intent}` | 답변 카드 (요지/전략/답변 2개+KR, NDJSON 스트리밍). intent: answer·agree·disagree·ask·propose |
| `POST /api/live/summary` `{transcript, mode}` | mode=line: 실시간 한 줄 요약 / full: 전체 정리 (스트리밍) |
| `POST /api/translate` `{text}` | KR↔EN 자동감지 번역 (스트리밍) |
| `GET /api/interview/question·categories·status` | 연습 모드 질문 은행 |
| `POST /api/interview/answers·feedback` | 연습 모드 모범답변/STAR 피드백 |
| `GET /health` (`?probe`로 재검사) | 활성 공급자/모델 + 공급자별 실제 연결 상태(`llm` 배열) |
| `GET /api/kb/health` | 📊 내 데이터 진단 — 점수, 미입력 항목 위치, 개선 팁 |
| `POST /api/live/reset` | 세션 맥락(사용한 사례·직전 질문) 초기화 |

## ☁️ 클라우드 배포 (고정 URL)

Render 무료 티어로 고정 HTTPS URL을 만들 수 있다 (저장소 루트의 `render.yaml` 사용):

1. [render.com](https://render.com) 가입 (GitHub 계정 연동)
2. **New → Blueprint** → 이 저장소 선택 (`render.yaml` 자동 인식)
3. 환경변수 2개 입력:
   - `GROQ_API_KEY` — console.groq.com에서 발급한 키
   - `ACCESS_CODE` — **접속 코드 (필수!)** 본인만 아는 값. 고정 공개 URL이므로
     이 코드가 없으면 URL을 아는 누구나 내 Groq 키로 API를 쓸 수 있다.
4. Deploy → `https://interview-coach-xxxx.onrender.com` (아이폰 홈 화면 추가 OK)

접속하면 코드 입력 화면이 먼저 뜨고, 한 번 입력하면 30일간 유지된다.

**무료 티어 주의사항**:
- 15분간 접속이 없으면 잠들고, 첫 접속에 30초~1분 걸린다 → **면접 5분 전에 미리 접속**해 깨워둘 것
- 디스크가 배포/재시작 시 초기화된다 → 프로필/스토리 수정은 저장소에 커밋(자동 재배포),
  ⚡ 맞춤 답변셋은 재시작 후 버튼으로 다시 생성 (약 1분)
- 로컬 실행(`bash start.sh`)은 `ACCESS_CODE` 미설정 시 게이트 없이 그대로 동작

## LLM 자동 전환 (Groq → Cerebras → Gemini → Ollama)

번역·답변·요약·리포트의 모든 LLM 호출은 공급자 체인을 순서대로 시도한다.
**퀄리티 유지가 원칙**이라 70B급 클라우드가 앞순위, 로컬 소형 모델은 최후 보험이다:

1. **Groq** (llama-3.3-70b) — 가장 빠름. 단, 일부 회사망 프록시가 api.groq.com을 차단(403)
2. **Cerebras** (llama-3.3-70b, OpenAI 호환) — Groq과 같은 70B급 오픈소스 모델을
   무료 1M토큰/일로 서빙. 도메인(api.cerebras.ai)이 달라 Groq이 막힌 회사망에서도
   뚫릴 수 있다 ([cloud.cerebras.ai](https://cloud.cerebras.ai)에서 무료 키 발급).
   `CEREBRAS_MODEL=qwen-3-235b-a22b-instruct-2507`로 바꾸면 한국어 품질이 더 올라간다
3. **Gemini** (gemini-2.5-flash) — 구글 도메인이라 회사망 통과율이 가장 높고 무료 키 발급 즉시 가능
   ([aistudio.google.com/apikey](https://aistudio.google.com/apikey))
4. **Ollama** (설치된 모델 자동 감지, 권장 `qwen3:8b`) — 완전 오프라인 보험.
   답변 카드 완성이 8~12초로 느려지므로, 로컬 폴백에 자주 의존한다면
   **⚡ 맞춤 답변셋 사전 생성**을 미리 돌려 빈출 질문을 0초 캐시로 커버할 것

- 401/403/404/429나 연결 실패가 난 공급자는 **60초간 건너뛰고** 다음 공급자로 즉시 전환
  → 면접 중 한 공급자가 죽어도 답변 흐름이 끊기지 않는다.
- 서버 시작 시 각 공급자에 초소형 검사 요청을 보내 **✅/❌ 상태를 배너로 출력**하고,
  라이브 페이지도 `/health`를 읽어 살아있는 공급자가 없으면 상단에 경고를 띄운다.
- 순서 변경: `LLM_ORDER=gemini,groq,ollama` 처럼 환경변수로 조정.
- **STT(Whisper 배치 엔진)는 Groq 전용** — 하지만 기본 엔진인 브라우저(Web Speech)는
  서버 키와 무관하게 동작하므로, Groq이 막혀도 실시간 자막은 정상.

API 키는 코드/저장소에 넣지 말고 환경변수로만 관리할 것.
