# HOTFIX-RULES — 실측 후 수정이 필요할 때의 규칙

> 코드는 `v1.0.0-interview`로 동결됐다 (2026-08-23). 이 문서는 그 이후의
> 모든 수정이 따라야 하는 규칙이다. 목적은 하나 — **8/27 전에 "검증된 상태"를
> 잃지 않는 것.** 잘 도는 앱을 마지막 주에 더 좋게 만들려다 망가뜨리는 것이
> 가장 흔한 실패다.

## 규칙 1 — 증거 없는 수정은 착수하지 않는다

수정 요청에는 아래 중 하나 이상의 **실측 증거**가 첨부되어야 한다:

- `bash meeting-copilot/incident.sh 60` 출력 (API 오류·지연 구간 진단 블록)
- `bash meeting-copilot/smoke.sh` 의 🔴 구간 (docs/REPORT.md 10.1절 자동 기록)
- `bash meeting-copilot/preflight.sh` 의 ❌ 판정 줄
- 화면 캡처 + 재현 절차 ("이 버튼을 누르면 이렇게 된다" 수준으로 구체적으로)

"느낌상 느린 것 같다", "이것도 있으면 좋겠다"는 착수 사유가 아니다 —
전자는 증거를 먼저 수집하고, 후자는 8/27 이후로 미룬다.

## 규칙 2 — 최소 수정, 리팩토링 금지

- 수정 범위는 **해당 결함을 없애는 최소한**으로 한정한다.
- 수정하는 김에 정리·개선·구조 변경을 얹지 않는다. 그 파일이 아무리
  지저분해 보여도, 동결 기간의 리팩토링은 검증되지 않은 변경일 뿐이다.
- 신규 기능은 결함 수정이 아니다 — 전부 8/27 이후.

## 규칙 3 — 수정 후 재검증은 표적만

| 수정한 곳 | 재실행할 것 |
|---|---|
| 검색·시드 (`rag.py`, corpus) | `rag_eval.py` + `ooc_eval.py` |
| 프롬프트·생성 (`prompts.py`) | `ooc_eval.py` + `speakability.ts` |
| 호출·한도 (`llm.py`, `gateway.py`) | `resilience-sim.mjs` + **15분 시뮬**(`rpm-sim.mjs`) |
| 화면 (`app.html`) | `e2e.mjs` |
| 서버·인증 (`server.py`, `auth.py`) | `web_qa.py` + `e2e.mjs` |

- 어떤 수정이든 **15분 시뮬은 재실행**한다 (실시간 경로의 최종 관문).
- **전수 재검증(REPORT 18장 배터리)은 구조 변경 시에만** — 그리고 동결
  기간에 구조 변경이 필요해 보인다면, 그것은 수정이 아니라 8/27 이후의 일이다.

## 규칙 4 — 되돌릴 수 있게

- 수정 1건 = 커밋 1건 (conventional commit + 증거를 커밋 메시지에 요약).
- 수정이 꼬였거나 확신이 없으면 즉시 복귀: `git checkout v1.0.0-interview`
- 복귀는 실패가 아니다 — 검증된 상태로 인터뷰에 들어가는 것이 목표다.
