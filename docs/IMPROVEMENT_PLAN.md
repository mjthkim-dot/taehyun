# 면접 어시스턴트 품질 개선 — 진단과 계획

기준 커밋 `86689a0` · 앱 v5.3 · 작성 2026-08-27 · **코드 변경 없음(진단만)**

---

## 0. 결론 먼저

**계획서의 원인 가설 두 개는 코드와 맞지 않는다.** 통 스크립트 주입도, 컨텍스트
누적도 이 코드베이스엔 없다(§1에 증거). 실전에서 겪은 지연의 실제 원인은 다른
데 있었고 v5.1에서 이미 제거됐다.

**그러나 계획서의 처방 방향은 여전히 옳다.** 이유가 다를 뿐이다. 남아 있는
진짜 문제는 **"근거가 없어도 무조건 답을 만든다"**는 것이다(원칙 4 위반이
프롬프트에 명문화돼 있다). 사전 컴파일은 지연이 아니라 **환각 차단**을 위해
필요하다.

가장 먼저 고칠 단 하나: **§4의 미스 처리(Tier C)**. 사전 컴파일보다 먼저다.

## 1. 원인 가설 검증 — 증거

### 가설 A. "스크립트를 분할 없이 통으로 주입했다" → **사실 아님**

| 항목 | 실제 동작 | 근거 |
|---|---|---|
| 코퍼스 주입 방식 | 검색 상위 **3건만** | `prompts.py:111` (`k: int = 3`), `:129` |

코퍼스는 218청크로 색인돼 있고 통으로 들어간 적이 없다.

### 가설 B. "30분 세션 동안 컨텍스트가 누적된다" → **사실 아님**

맥락 입력을 43배 늘려도 프롬프트는 **10자** 변한다.

| 맥락 입력 | 프롬프트 크기 |
|---|---|
| 7턴 (391자) | 7,759자 |
| 50턴 (2,839자) | 7,764자 |
| 300턴 (17,289자) | **7,769자** |

3중으로 잘린다: `app.html:1360` 최근 7턴 → `server.py:612` 3,000자 →
`prompts.py:122` 최근 5줄. **원칙 3은 이미 충족돼 있다.**

### 그럼 실전에서 왜 느렸나 (v5.1에서 규명·수정 완료)

1. 턴 병합이 조각마다 재발사 → 직전 생성을 계속 abort. 질문 1개에 **8회** 발사.
   버려진 오프너가 fast 레인을 점유해 번역까지 밀렸다.
2. 모델이 무제한으로 생각 → `queued=0ms`인데 `latency=52,317ms` 관측.
3. 서버 전사 왕복 4.73초(당시 권장 모드).

실측 개선: 답변 지연 p50 2.00→**0.92초**, 최대 15.61→**1.13초**.
(근거: `docs/REPORT.md §49`)

**"부적절한 답변셋"의 원인도 같다.** STT가 "Workato→avocado"로 깨진 텍스트가
검색 질의로 들어갔다. 검색 자체는 멀쩡했다(§2-3).

## 4. 가장 먼저 고쳐야 할 단 하나

### 미스(Tier C) 시 "생성하지 않기" — `prompts.py:188` 무력화

**무엇**: 검색이 컷을 통과하지 못하면(`_strong_hits`가 빈 배열) 답변을 만들지
않고, 확정 사실·키워드만 표시하고 "대본 없음"을 명시한다.

**왜 첫 번째인가**
1. **위험이 가장 크다.** 화면 문장은 그대로 발화된다. 지연은 어색함을 낳지만
   환각은 **거짓 경력 진술**을 낳는다. 되돌릴 수 없다.
2. **가장 싸다.** 사전 컴파일(40~60유닛)은 며칠짜리 작업이지만 이건 분기 하나와
   프롬프트 한 줄이다.
3. **사전 컴파일의 전제다.** 미스를 감지·기록해야(§5-4) 무엇을 컴파일할지
   알 수 있다. 지금은 미스가 그럴듯한 답으로 덮여 **보이지 않는다.**
4. 실측상 10문항 중 1건이 이미 컷 탈락 후 프로필로 답하고 있었다 — 사용자는
   그것이 대본 기반인지 아닌지 구분할 수 없다.

**작업량**: `prompts.py` 분기 + `server.py` 메타 필드 + `app.html` 표시 —
반나절. e2e 계약 1건.

## 6. 코드만으로 판단 불가 — 확인 요청 5개

1. **L1~L4 16개 구성요소의 정확한 정의.** §3은 내 해석이다. 실제 프레임워크의
   16개 항목명을 주시면 그 축으로 다시 매핑하겠다.
2. **다음 면접 대상 회사.** 현재 코퍼스는 Workato 중심(제품 라인·재무 팩트)에
   GitLab 피치가 얹혀 있다. 답변 유닛 40~60개를 **어느 회사 기준**으로
   컴파일할지에 따라 작업 내용이 달라진다.
3. **KR·PR을 실전에서 실제로 읽는가.** §5 Phase 1의 -1.5초는 이 둘을 후순위로
   미루는 대가다. 면접 중 한국어 뜻과 한글 발음 중 무엇을 보는지 알려달라.
   (안 본다면 아예 끄는 것이 가장 빠르다)
4. **Tier C에서 무엇을 보고 싶은가.** "대본 없음"만 띄울지, 확정 수치 + 키워드
   + 시간 벌기 문장("Let me think about that for a second")까지 줄지.
5. **무료/유료 티어 전제.** Phase 1이 호출 수를 늘린다. 유료 유지가 확정이면
   그대로 진행, 아니면 KR·PR 분리 대신 PR만 제거하는 축소안으로 간다.
