# AUDIT — 수용 기준 대비 현재 상태 감사 (2026-08-22)

> 방식: 코드 전수 열람 + 실행 중인 앱에 트랜스크립트를 주입해 실측.
> 수치는 로컬 모의 LLM 기준(실 Claude 지연은 별도 표기), 스크린샷·테스트 로그는 REPORT.md에.

## 2. 갭 목록 (이번 스프린트에서 구현)

1. **수업용 질문 리스트** — 미팅에서 못 알아들었을 구간·막힌 표현을 근거로
   "진옥 선생님께 물어볼 것"을 별도 생성. 복습 탭·마크다운·Notion 저장에 포함
2. **번역 대기 표시** — 상대 발화 아래 은은한 `···` 로딩 상태
3. **데스크톱 최대폭** — 콘텐츠 660px 상한(사이드 패널 폭과 동급), 넓은 화면
   중앙 정렬. "미팅 옆에 좁게 두는" 사용 방식과 일치

## 3. 기술 리스크

| 리스크 | 현재 완화 | 잔여 |
|---|---|---|
| STT 안정성 — Web Speech는 Chrome 전용, 네트워크 인식이라 변동 | 탭 캡처→VAD→Whisper 대체 경로, 재시작 로직 | 실기기 인식 정확도 미실측 (모의 불가 영역) |
| RAG 지연 | N+1 제거+검색 직렬화로 동시 8에서 p50 105ms, 사용자별 락 분리 | 임베딩 활성 시(bge-m3) 질의당 +수십 ms — 미실측 |
| API 비용 | 발화당 1.25콜 실측, 번역 캐시·요약 합류, 사용자별 15/분·600/일 쿼터 | 쿼터가 호출 수 기준(토큰 아님) — 근사치 |
| LLM 형식 준수 | 모의는 항상 준수 — **실모델의 15단어·EN/KR 형식 준수율 미실측** | 배포 첫날 실 키 스팟체크 필요 |

## 4. RAG 임베딩 방식 비교 (결정 기록 — 상세는 ARCHITECTURE.md 4장)

| 방식 | 비용 | 한↔영 교차 검색 | 판단 |
|---|---|---|---|
| transformers.js (브라우저) | $0 | 소형 모델은 교차언어 약함, 첫 로딩 수십 MB, 탭마다 재로딩 | ✗ 미팅 중 탭이 무거워지는 건 실시간성에 역행 |
| 서버리스 임베딩 API | 종량 과금 | 좋음 | ✗ $0 원칙 위배 + 트랜스크립트가 외부로 나감 |
| **SQLite + 로컬 임베딩(bge-m3) + BM25 폴백** | **$0** | **bge-m3가 강함, 없어도 키워드 다리로 동작** | ✅ 채택 — 개인 규모(수천 청크)에 ANN 불필요, 파일 1개 백업, 데이터가 기기를 떠나지 않음 |

sqlite-vec(확장)은 채택하지 않았다: pip 의존성이 생기고, 실측상 브루트포스
코사인이 이 규모에서 충분히 빠르다(1,700청크 p50 15ms).
