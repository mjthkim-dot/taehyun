## 2. 갭 (이번 미션의 실제 작업)

### G1 — Notion 수업 노트 연동: **없음** (P0)
- `app/api/lessons/route.ts`는 "실제로는 Notion에서 조회한다"는 주석뿐인
  하드코딩 샘플. 실제 연동 코드 0줄.
- **Notion 실사 결과**: 수업 노트는 DB가 아니라 **"영어 진옥" 페이지 트리**
  (1회차 인라인 미팅노트 + 2~7회차 자식 페이지 + 📚 학습 누적 정리).
  누적 정리 페이지에는 "보이스 어시스턴트 앱의 SRS 복습에 약점 표현으로
  등록 / 회차별 문법·표현을 커리큘럼 데이터로 반영"이라는 명시적 통합 지시가
  이미 적혀 있다 — 이 미션은 그 지시의 이행이다.
- 노트는 자유 서식(미팅노트 요약+전사)이라 서버 정규식 파싱은 취약 →
  구조화는 앱의 기존 AI 계층(aiGuard 검증 파이프라인)이 적임.
- 스키마 제약: 브리프의 "양방향 동기화" 중 **Notion으로의 자동 쓰기**는
  에스컬레이션 경계(자동 발송·자동 쓰기) → 읽기 동기화만 자율 구현,
  쓰기는 사용자 확인 후.

### G2 — Lighthouse: **미측정** (P0)
- 자체 perf 하니스(모바일 4× 스로틀)는 상시 운용 중이나 Lighthouse
  Performance/Accessibility/Best Practices 점수는 한 번도 측정한 적 없음.

### G3 — AI Tutor의 "Claude API 기반": **Groq(무료) 사용 중** (에스컬레이션)
- 현재 llama-3.3-70b(Groq 무료 티어) + aiGuard 방어 계층. Claude API 전환은
  **유료 결제 결정** → 에스컬레이션 경계. 자율 전환하지 않고 보고서에서 질의.
- 튜터의 교차 세션 기억(지난 대화 요약을 다음 대화에 주입)은 무료로 개선
  가능한 갭 → P1로 수행.

### G4 — 빈/에러 상태 잔여 감사 (P1)
- 대부분 설계돼 있으나(무음 실패 제거 이터레이션 완료), Notion 연동 신설
  화면은 미설정/오프라인/실패/빈 상태 4종을 처음부터 설계해야 함.
