# FIELD-TEST — 실전 검증 체크리스트 (비개발자용)

## ⭐ 실전 당일 최종 체크 (v5.4 기준, 5분)

1. `cd ~/taehyun && git pull` → `cd meeting-copilot && bash start.sh`
2. 크롬 ⌘⇧R → 헤더 배지 **v5.4** 확인 (다르면 한 번 더 ⌘⇧R)
3. 상단 설정: 프리셋 **🎤 인터뷰** · 모드 **🔒 실미팅** · 레벨 **B2**
4. **인식 엔진 = 🎤 브라우저(실시간)** ← v5.1에서 권고가 바뀌었습니다.
   v5.0에서 권했던 🎧 정밀 모드는 정확하지만 **말이 끝나고 2.5초 뒤에야** 자막이
   떠서 전부 느려집니다. v5.1은 "mega stone crab→MegazoneCloud, avocado→Workato"
   같은 오인식을 **지연 0으로 교정**하므로, 실시간이 중요한 면접에선 🎤가 낫습니다.
   BlackHole 라우팅은 기존 그대로 (상태줄 **BlackHole=상대 전용** 확인).
   · 녹화본 리뷰처럼 정확도가 최우선이면 🎧 정밀 (v5.1에서 2초 빨라졌습니다).
5. 자료 탭 → 청크 수 (Workato 코퍼스 포함) 확인
6. ▶ 시작 → 🪟 오버레이 → 🎦 눌러 Zoom 창 선택 (얼굴이 패널 뒤로)
7. 유튜브 영어 문장 하나로: 자막 → KR 번역(1초 이내) → 답변 카드 확인
   · 질문이 여러 조각으로 들려도 **말이 끝나면** 답변이 1회만 생성됩니다(v5.1).
     그 전에 ⚡오프너가 첫 문장을 먼저 띄우니 바로 말을 시작하면 됩니다.
8. 문제가 생기면 그 자리에서: `bash incident.sh` 출력을 저장해 두기
   (🎧 인식이 계속 실패하면 엔진을 🎤 브라우저로 바꾸면 예전 방식으로 복귀)
9. 답변 읽는 법: **/ 표시에서 끊어 읽기**. v5.4부터 답변 카드는 **영어만**
   나옵니다(한국어 뜻·한글 발음 줄 제거 — 안 보신다고 하셔서 뺐고, 그만큼
   1.2초 빨라졌습니다). 되돌리려면 `ANSWER_LINES=en,kr,pr bash start.sh`
   · 붉게 표시된 숫자 = **내 자료에 없는 값**입니다. 그대로 읽지 마세요
   · 노란 **📭 대본 없음** 배너 = 근거를 못 찾아 답을 만들지 않았다는 뜻입니다.
     화면의 시간 벌기 문장으로 한 박자 쉬고, 아는 사실만 말하세요
10. 새 질문인데 카드가 안 바뀌면: 호박색 "⤴ 이전 발화" 라벨 확인 후
    [💬 그냥 답하기] 클릭 — 즉시 새 답변 생성 (최근 10초 발화를 한 턴으로
    묶어 질문 맥락을 통째로 반영)

> 샌드박스에서 검증 못 한 3가지(실제 마이크 · 실 LLM API(Gemini) · Whisper 모델)를
> 내 맥북에서 직접 확인하는 절차. 30분이면 끝난다.
> 코드는 `v1.0.0-interview` 태그로 동결됨 — 이상하면 `git checkout v1.0.0-interview`.

## 0. 준비 (딱 3개 명령)

```bash
export GEMINI_API_KEY=...              # 키를 넣고 (aistudio.google.com/apikey)
bash meeting-copilot/doctor.sh         # ① 사전 점검 — ❌가 없어질 때까지
bash meeting-copilot/smoke.sh          # ② 구간별 테스트 — 마이크로 한 문장 말해보기
```

**실전 당일 아침**은 위 전체 대신 30초 축약판 하나만:

```bash
bash meeting-copilot/preflight.sh      # 마지막 줄이 판정: ✅ 실전 투입 가능 / ❌ 항목—조치
```

- `doctor.sh`: 마이크·키(실 호출 1회)·Whisper 모델·포트를 점검하고, 문제면
  **해결 명령까지** 알려준다. Whisper 다운로드(145MB, 1~3분)는 물어보고 진행.
- `smoke.sh`: 마이크→STT → 번역 → 검색 → 제안을 **구간별로** 검증해
  어느 구간이 문제인지 바로 보여주고, 실측 지연(ms)을 `docs/REPORT.md` 10.1절에
  자동 기록한다. 기준 미달 구간은 🔴로 표시된다.
- 마이크 없이 나머지만 보려면: `bash meeting-copilot/smoke.sh --skip-mic`

둘 다 통과하면 `bash meeting-copilot/start.sh` 로 앱을 켠다.

## 1. 유튜브 영어 회의 영상 고르기

실전과 같은 조건이 되도록 이 기준으로 고른다:

| 조건 | 이유 |
|---|---|
| **화자 1~2명**, 서로 말 겹침(크로스토크) 없는 것 | 앱은 화자 겹침을 못 푼다 — 실제 화상회의도 대부분 한 명씩 말한다 |
| **자연스러운 대화 속도** (너무 빠른 패널 토론 ✗) | 실전 미팅 속도 재현 — earnings call, 1:1 인터뷰, 제품 데모 Q&A가 적당 |
| **비즈니스 주제** (클라우드/IT/세일즈면 최적) | 용어집·수업 노트가 검색될 소재가 있어야 RAG 차별점이 보인다 |
| **자막(CC) 있는 영상** | 앱의 자막과 유튜브 자막을 비교하면 인식 정확도를 눈으로 판정할 수 있다 |
| 15분 이상 | 롤링 요약·복습 자산화까지 보려면 짧은 클립으론 부족하다 |

검색 예: "AWS re:Invent fireside chat", "SaaS sales discovery call example",
"enterprise software earnings call" 등.

**연결 방법 (택1)**
- 🎤 **브라우저(실시간) 모드**: 노트북 스피커로 영상을 틀고, 앱(▶)이 스피커
  소리를 마이크로 듣게 한다. 이어폰을 끼면 앱이 못 듣는다는 점만 주의.
- 🖥 **탭 오디오 모드**: 이어폰을 껴도 된다. 공유 창에서 유튜브 탭을 고르고
  **"탭 오디오도 공유"를 반드시 체크**.

## 3.4 코드를 Claude에 보내 분석시키기

앱 소스를 붙여넣기 좋은 **7조각**으로 잘라 준다. 미팅 기록·개인 노트·API 키는
들어가지 않는다(포함 파일이 화이트리스트로 고정돼 있다).

**앱에서** — '자료' 탭 → 🧩 코드를 Claude에 보내기 → [1번 복사] → Claude에 ⌘V →
[2번 복사] → ⌘V … 7번까지 넣은 뒤 질문한다.

**터미널에서** — 파일로 받아 드래그하는 쪽이 더 편하다:
```bash
cd ~/taehyun/meeting-copilot
python3 tools/code_bundle.py          # 바탕화면 meeting-copilot-code/ 에 7개 파일
python3 tools/code_bundle.py 2        # 2번 조각만 클립보드로
python3 tools/code_bundle.py all      # 한 파일로 (드래그 첨부용)
python3 tools/code_bundle.py json     # JSON 구조로 (파일 경계가 명확 — 분석에 유리)
```

JSON은 파일마다 `path·lang·purpose·lines·content`가 들어 있어 Claude가 경계를
헷갈리지 않는다. 묶음별 파일도 **각각 그 자체로 유효한 JSON**이라 나눠 넣어도 된다.
(직접 받으려면 `localhost:3799/api/code?fmt=json`, 묶음만은 `&g=1`~`&g=6`)

⚠️ 폰이나 `trycloudflare.com` 주소에서는 이 기능이 **일부러 막혀 있다** — 그 주소는
공개라, 열어두면 누구나 앱 소스를 가져갈 수 있기 때문이다. 맥에서
`localhost:3799`로 연 창에서만 동작한다.

## 3.5 화자 분리 — BlackHole로 상대 목소리만 잡기 (권장 설정)

일반 마이크 모드는 스피커에서 나오는 상대 소리와 **내 목소리를 구분하지
못한다** — 내 말까지 자막·제안을 유발한다. BlackHole(설치돼 있음)로 상대
소리만 앱에 넣으면 완전한 화자 분리가 된다. **한 번만 설정하면 된다.**

**① 다중 출력 기기 만들기** (상대 소리를 스피커와 BlackHole에 동시 전달):
Spotlight(⌘+Space)에서 "Audio MIDI 설정" 실행 → 좌하단 **+** → **다중 출력
기기 생성** → 목록에서 **MacBook Pro 스피커**와 **BlackHole 2ch** 둘 다 체크
→ 이름을 "면접용"으로 변경.

**② 시스템 출력을 "면접용"으로**: 시스템 설정 → 사운드 → 출력 → **면접용**
선택. (Zoom·유튜브·Meet 소리가 스피커로도 들리고 BlackHole로도 복사된다)
⚠️ 다중 출력 상태에서는 키보드 볼륨 조절이 안 될 수 있음 — 미리 볼륨을
맞춰두거나, 사운드 설정에서 개별 기기 볼륨을 조절한다.

**③ Chrome 마이크를 BlackHole로**: Chrome 주소창에
`chrome://settings/content/microphone` 입력 → 상단 드롭다운에서
**BlackHole 2ch** 선택. (앱이 듣는 입력이 '내 마이크'→'상대 소리 복사본'으로 바뀐다)

**④ Zoom 마이크는 진짜 마이크 유지**: Zoom 설정 → 오디오 → 마이크 =
**MacBook Pro 마이크** (면접관이 내 목소리를 듣는 경로 — 건드리지 않으면 기본값).

**확인**: 상태줄에 **"🎧 상대 전용(BlackHole) — 화자 분리 ON"** 이 초록으로 떠야 한다.

**v5.3부터 — ③을 건너뛸 수 있는 길**: 헤더에 **입력 장치 목록**이 생겼다.
거기서 `🎧 BlackHole 2ch`를 고르면 **앱이 그 장치를 직접 지정**하므로 Chrome
기본 설정과 무관하게 분리가 보장된다(BlackHole이 보이면 자동으로 골라 둔다).

⚠️ 단, 이 방식은 **🎧 마이크 정밀 · 🖥 탭 오디오 모드에서만** 통한다.
**🎤 브라우저(실시간) 모드는 브라우저 규격상 입력 장치를 지정할 수 없어서**
③(Chrome 기본 입력을 BlackHole로)을 반드시 해야 한다. 상태줄에
"Chrome 기본 입력을 BlackHole로 바꾸세요"가 뜨면 그 뜻이다.

정리하면 — 실시간성(🎤)을 쓰려면 ③이 필수, ③이 귀찮으면 🎧 정밀 모드에서
장치를 직접 고르면 된다(대신 자막이 2.5초 늦다).

**되돌리기** (면접 후): 시스템 출력 → MacBook Pro 스피커, Chrome 마이크 →
기본값.

## 4. 인터뷰 리허설 (8/27 HR 스크리닝 대비)

유튜브 테스트를 통과했다면 리허설을 한 번 돌린다. 상단 프리셋을
**🎤 인터뷰**로 바꾸면 버튼이 [동의/부연 설명/되묻기/역질문]으로
바뀌고, 한→영 입력창이 버튼 위로 올라온다(`/` 키로 즉시 포커스).

**🪟 오버레이 (Zoom·Meet 전체화면 대비 — 리허설에서 꼭 한 번 써 볼 것)**:
헤더의 🪟 버튼을 누르면 자막·제안 창이 **모든 앱 위에 항상 떠 있는 작은 창**으로
바뀐다 (Chrome 116+). Zoom을 전체화면으로 켜도 가려지지 않는다.
- v2.4부터 창 안이 플로팅 패널이다: 위에서부터 [⏸⏹·라이브 바] →
  [호박색 실시간 요약 스트립] → [답변 카드] → [자막 1~2줄] →
  [동의/반박/질문/제안] → [라운드 입력창]. ⏸는 듣기 일시정지, ⏹는 미팅 종료
  (본창 버튼과 완전히 연동).
- 바의 [S/M/L]로 크기 프리셋, [70%]로 반투명↔불투명(기본 반투명),
  [전체]로 카드가 하단으로 가는 전체 레이아웃 전환 — 전부 기억된다.
- **🎦 배경 비추기**: 누르고 공유 선택창에서 **Zoom(또는 Meet) 창**을 고르면
  그 화면이 패널 뒤에 비쳐 자막·답변 너머로 상대 얼굴이 보인다. 내 화면에서만
  렌더링되고 어디에도 전송되지 않는다. 다시 누르면 꺼짐. (PiP 창 자체의
  진짜 투명은 Chrome이 막고 있어 이 방식이 유일한 우회다)
- 작은 창을 상대 얼굴 근처(시선 이동 최소 위치)로 끌어다 두고, 모서리를 잡아
  크기를 조절해도 된다 — 크기도 기억된다.
- 마이크·인식은 원래 탭에서 계속 돈다. **원래 탭을 닫으면 인식도 멈춘다** —
  탭은 백그라운드에 그대로 두면 된다.
- 작은 창의 X(또는 🪟 재클릭)를 누르면 원래 화면으로 복귀한다.
- 단축키는 작은 창에서도 동작: Space 고정 / Esc 닫기 / +·- 글자 크기.

리허설 시나리오는 둘 중 편한 것 하나 (A가 더 간단, B가 더 실전적):

- **A. 유튜브 모의 인터뷰 영상**: "mock interview HR screening" /
  "sales job interview questions and answers"로 검색해 면접관이 질문을
  던지는 영상을 고른다. 질문이 나올 때마다 **일시정지하고 소리 내어 답한다** —
  앱이 질문을 자막·번역하고, 막히면 퀵 리액션/`/` 퀵 번역을 실제로 써 본다.
- **B. 음성 AI 면접관**: Gemini Live(제미나이 앱의 음성 대화) 같은 음성 AI에게
  "영어로 B2B 세일즈 직무 HR 스크리닝 면접관 역할을 해줘. 한 번에 질문
  하나씩"이라고 시키고, 그 대화를 스피커로 틀어 둔 채 앱을 켠다.
  예상 못 한 후속 질문이 나오므로 실전과 가장 가깝다.

리허설에서 확인할 5가지 — 기능이 아니라 **"실전에서 정말 의지되는가"**를 본다:

| # | 확인 항목 | 무엇을 보나 | 안 되면 |
|---|---|---|---|
| 1 | **자막을 힐끗 볼 여유가 있는가** | 대화에 집중하면서 시선을 0.5초만 줘도 요지가 잡히는가. 오히려 대화를 방해하면 실전 투입 불가 | 글자 크기(🔎)를 키우고, 번역만 보고 영어 자막은 무시하는 연습 |
| 2 | **퀵 리액션을 실제로 누르게 되는가** | 리허설 중 최소 2번, 진짜 막힌 순간에 눌러서 나온 문장을 읽어보기 | 누를 틈이 없으면 → `/` 퀵 번역만 쓰는 전략으로 전환 (이게 더 실전적) |
| 3 | **배너·카드가 시야를 방해하지 않는가** | 화상 화면 옆 400px 창 기준, 상대 얼굴을 보는 데 걸리적거리는 게 있는가 | 카드는 Esc로 닫고 📌 고정은 쓰지 않기, 창을 더 좁혀보기 |
| 4 | **폰트 크기가 거리에서 읽히는가** | 모니터에서 팔 하나 거리로 떨어져 힐끗 — 번역이 읽히는가 | 🔎 버튼(100/118/140%)으로 확대, 그래도 작으면 브라우저 줌 |
| 5 | **종료 자산화가 쓸 만한가** | ⏹ 후 복습 탭: 표현 10개가 진짜 이번 수업에서 나온 것인가, 수업 질문이 말이 되는가 | 품질이 낮으면 그 화면을 캡처해 아래 5절 방법으로 전달 |

리허설에서 **한 번이라도 실제로 도움이 됐다면** 8/27 투입 가능 판정.
반대로 시선이 자꾸 앱으로 끌려가 대화가 끊겼다면, 실전에서는 퀵 번역
단독 사용(자막 창 최소화)으로 범위를 줄이는 것이 정답이다.
