## 초록 (Abstract)

당근은 2025년 연결 매출 2,707억 원(YoY +43%), 별도 영업이익 671억 원을 기록하며 흑자를 굳혔으나, 2026년 1분기 매출 783.8억 원을 단순 연환산하면 성장률은 **+16%대로 둔화**된다. 동시에 자회사(당근페이·캐롯 해외법인)의 연결 매출 기여는 **17억 원**에 불과한 반면 연결 영업이익을 **525억 원** 훼손한다.

본 분석은 당근의 클라우드 원가율을 **매출의 약 10.3%**로 추정하고, 이 값이 추정 영업이익률(약 12.8%)과 **거의 동일한 크기**라는 점을 확인한다. 이로부터 **클라우드 비용 10% 절감이 영업이익 약 8% 증가와 등가**라는 관계가 도출된다. 이는 MZC가 CFO 라인에 제시할 수 있는 단일 최강 논거다.

또한 본 분석은 (i) 당근의 AWS-GCP 이원 구조가 전략적 선택이 아니라 **경로의존성의 누적 결과**이며, (ii) 당근의 AI 성숙도가 2026년 9월을 기점으로 **'내부 통합'에서 '대외 매출 채널'로 전이**했고, (iii) 분산 의사결정 구조에서 전사 단위 제안의 채택 확률이 **수학적으로 무의미한 수준**임을 보인다. 이 세 가지는 각각 DW 전환 제안의 스코프 축소, 판매 가능 품목의 재정의, 침투 경로의 순차화라는 전략적 처방으로 이어진다.

마지막으로 MZC의 포지션을 정량 분석한다. 2026 목표 갭 18.9억 원은 **리셀 마진 3.73%p와 등가**이며, 이는 갭을 할인으로 메우려는 시도가 **자기모순**임을 의미한다.

## II. 비즈니스 모델의 구조 — 로컬 네트워크 효과의 수익 방정식

### II-1. 수익 방정식

당근의 매출은 근사적으로 다음 형태를 갖는다.

```
매출 ≈ Σ(지역)  [ 공급밀도 × 수요밀도 × 매칭품질 ] × 광고 전환율 × 단가
```

여기서 결정적인 항은 **매칭품질**이다. 공급·수요 밀도는 이미 포화에 가깝고(누적 가입자 4,300만, MAU 2,100만 — 국내 경제활동인구 대비 상당 수준), 지역 단위로 쪼개지면 **각 지역의 밀도는 작다.** 즉 당근의 성장 여력은 유저 확대가 아니라 **좁은 지역 안에서의 매칭 정확도**에서 나온다.

이 구조가 세 가지를 설명한다.

**(a) 왜 ML 투자가 매출에 직결되는가.** 테크블로그의 **"지역 제약을 반영한 RCBS(Region-Constrained…)"** 와 **"장기 유저 로그 기반 Transformer 유저 임베딩"** 은 학술적 관심사가 아니라 매칭품질 = 매출 항을 직접 개선하는 작업이다. 그래서 GPU 비용은 당근에서 **비용이 아니라 매출원가**로 취급된다.

**(b) 왜 광고주 증가율(+37%)보다 매출 증가율(+43%)이 높은가.** 매칭품질이 올라가면 동일 광고주에서 더 많은 매출이 나온다. 즉 **ARPA(광고주당 매출) 상승**이 관측된다. `[CONFIRM: 매출 전액이 광고는 아니므로 근사]`

**(c) 왜 비즈프로필 265만이 다음 레버인가.** 밀도가 포화라면 남은 성장은 **이미 플랫폼에 있는 소상공인의 광고주 전환**이다. 그리고 그 전환의 병목은 "소상공인이 광고 성과를 해석하지 못함"이다 — 2026.9.16 **당근 광고 MCP**가 정확히 이 지점을 겨냥한다.

### II-2. 구조적 천장

| 항목 | 값 | 함의 |
|---|---|---|
| 누적 가입자 | 4,300만 | 국내 시장 사실상 포화 |
| MAU | 2,100만 | — |
| 2026 추정 ARPU (A2/A6) | **14,929원/년** | 3,135.2억 ÷ 2,100만 |
| 중고거래 건수 (2025) | 1.9억 건 | **무료 서비스 — 순수 원가** |

> **중고거래는 매출을 만들지 않는다.** 1.9억 건의 트랜잭션·채팅·이미지 처리는 전부 비용이고, 회수는 광고에서 일어난다. 즉 당근의 손익 구조는 **"대규모 무료 트래픽을 광고로 회수하는" 구조**이며, 이 구조에서 **클라우드 원가율은 곧 마진율의 상한을 규정한다.**

## III. 단위경제학 — 클라우드 원가율 10.3%의 의미

### III-1. 클라우드 원가율 산출

```
AWS 연간      = $1.86M × 12 = $22.32M          (A3)
              = $22.32M × 1,400 = 312.48억 원   (A1)

GCP 연간      = $800K × 1,400 = 11.20억 원      (A4, 과소추정)

총 클라우드    = 312.48 + 11.20 = 323.68억 원

2026 매출     = 783.8억 × 4 = 3,135.2억 원      (A2)

∴ 클라우드 원가율 = 323.68 ÷ 3,135.2 = 10.32%
```

### III-2. 영업이익률과의 비교 — 본 분석의 핵심 관계

```
2026 추정 영업이익 = 200억 × 2 = 400억 원        (A5)
2026 추정 영업이익률 = 400 ÷ 3,135.2 = 12.76%
```

| 지표 | 값 |
|---|---:|
| 클라우드 원가율 | **10.32%** |
| 추정 영업이익률 | **12.76%** |
| 비율 (클라우드 ÷ 영업이익) | **0.81** |

> **정리 1 (Theorem 1).**
> 당근의 클라우드 지출은 영업이익의 약 81% 크기다. 따라서
>
> ```
> 클라우드 10% 절감 = 323.68억 × 0.10 = 32.37억 원
> 영업이익 증가율    = 32.37 ÷ 400 = 8.09%
> ```
>
> **클라우드 비용 10% 절감은 영업이익 약 8% 증가와 등가다.**

이것이 왜 중요한가. 당근의 영업 조직이 광고 매출을 8% 늘리려면 광고주를 수천 개 더 유치해야 한다. **같은 이익 효과를 인프라 한 곳에서 만들 수 있다.** 이것이 CFO·CEO 라인에 제시할 수 있는 단일 최강 논거이며, 5월 Account Plan에 이 계산이 없었던 것이 **CFO 라인이 4개월간 열리지 않은 이유**일 수 있다.

### III-3. 사용자 단위 원가

```
사용자당 연 클라우드 원가 = 323.68억 ÷ 2,100만 = 1,541원/년 = 월 128원
사용자당 연 매출(ARPU)   = 14,929원/년
∴ 클라우드 / ARPU        = 10.3%
```

> **월 128원.** 이 숫자는 두 방향으로 쓸 수 있다.
> - **고객 방어 논리:** "사용자당 월 128원이면 싸다" → 절감 동기 약화
> - **우리 논리:** "월 128원 × 2,100만 명 = 월 27억. 여기서 10%면 월 2.7억" → **절대금액으로 전환해야 대화가 성립한다.**
>
> **원가 대화는 반드시 절대금액과 영업이익 비중으로 해야 한다. 단위원가로 하면 진다.**

### III-4. 원가율의 궤적 — AI가 원가율을 밀어올리고 있다

2026년 8월 실측(9/15 SBR)이 보여주는 방향:

| 항목 | 증감 (7월→8월) | 원인 |
|---|---:|---|
| **EC2** | **+$117,183 (+26%)** | GPU(g7e, g6) 증가, **8/11 Trainium trn2.3xlarge CapacityBlock**, EBS gp3 처리량·PIOPS |
| CloudFront | +$22,762 (+19%) | HTTPS-Proxy(POST/OPTIONS) 증가 |
| DynamoDB | +$20,235 (+13%) | Read/Write 일시 증가 |
| ElastiCache | +$13,989 (+13%) | r7g/m7g/r6g Valkey — **`karrot-llm-router-vllm`** 포함 |
| **Marketplace** | **-$160,298 (-61%)** | Okta 선납 영향 + **Bedrock 사용 감소 (Claude Opus 4.8, Sonnet 4.6)** |
| DataTransfer | -$22,971 (-6%) | MSK 트래픽 40%+ 감소 |

총계는 +0.6%에 불과하나(EDP·Support·Credit 제외 시 +1.7%), **구성이 근본적으로 변하고 있다.**

```
매니지드 AI(Marketplace/Bedrock)  →  자체 서빙(EC2 GPU/Trainium + vLLM)
```

> **정리 2 (Theorem 2).**
> 당근의 AI 비용은 **매니지드에서 자체 서빙으로 이전 중**이다. 증거는 셋이다.
> ① Marketplace -61%, 사유에 "Bedrock 사용 감소" 명시
> ② EC2 +26%, GPU·Trainium CapacityBlock 사용 개시
> ③ 계정별 증가 1위 **`karrot-neurondeepdive2026`**(+$24,430) — AWS Neuron 딥다이브 전용 계정
> ④ ElastiCache 증가 노드에 **`karrot-llm-router-vllm`** 명시
>
> 이는 규모의 경제 때문이다. 수억 건 요청 규모에서는 **토큰 단가 < 자체 서빙 단위비용**이 역전된다. LLM Router가 애초에 **"통합 접근·비용 관리·멀티프로바이더"** 를 설계 목표로 명시한 것은, 당근이 **프로바이더 전환 스위치를 의도적으로 만들어 두었다**는 뜻이다. 2026년 8월에 그 스위치가 당겨졌다.

**벤더 함의.** 이것은 AWS 이탈이 아니라 **AWS 내 이동**이다. Bedrock은 Marketplace 매출이고 GPU/Trainium은 Infra+Support 매출이다. MZC의 2026 목표에서 증분의 101.9%를 져야 하는 바로 그 줄이다. **따라서 "Bedrock으로 오세요"는 폐기하고, "자체 서빙을 더 싸게 하세요"로 전환해야 한다.** 구체적으로는 Neuron 컴파일 최적화, Trainium/Inferentia 전환 TCO, CapacityBlock 예약 전략이다.

## IV. 클라우드 아키텍처의 경로의존성 — 왜 BigQuery인데 AWS인가

### IV-1. 관측된 구조

| 레이어 | 스택 | 클라우드 |
|---|---|---|
| 서비스 인프라 | EC2, EKS, ECS, DynamoDB, ElastiCache, MSK, CloudFront, RDS | **AWS** |
| **메인 DW** | **BigQuery (단일)** | **GCP** |
| 이벤트 수집 | Pub/Sub → Dataflow → GCS / BigQuery, DLQ | GCP |
| ELT | DT Platform — Airflow 동적 DAG + **Spark on EMR/EKS**, JSON DSL, S3 경유 | **AWS + GCP 혼재** |
| 거버넌스 | 컬럼 리니지 (BigQuery INFORMATION_SCHEMA + sqlglot + Spark) | GCP |
| BI·지표 | Superset, KarrotMetrics, 실험 플랫폼 | GCP 기반 |
| AI 플랫폼 | LLM Router / Prompt Studio / KarrotChat | 혼재 `[CONFIRM]` |

당근이 직접 공개한 규모: **200개 이상 DB를 한국·일본·캐나다 리전 × alpha/prod 환경별로 BigQuery에 전송.** 컬럼 리니지는 **일 약 15,000개 테이블 / 80만 개 컬럼 의존관계**를 추적한다.

### IV-2. 경로의존성 가설

**가설.** 이 이원 구조는 의도된 멀티클라우드 전략이 아니라 **시기별 최적 선택의 누적**이다.

| 시기 | 선택 | 당시 합리성 |
|---|---|---|
| 창업 초기 | AWS로 서비스 구축 | 국내 스타트업 표준, 생태계 성숙 |
| 데이터 조직 형성기 | BigQuery를 DW로 채택 | 서버리스·운영부담 최소, GA/Firebase 연동, 당시 Redshift 대비 운영 편의 |
| 현재 | 두 구조가 고착, 상시 데이터 이동 발생 | — |

확신도: **중상.** 각 선택의 정확한 시점·사유는 공개되지 않았다. `[CONFIRM: 강진우 실장 확인]`

**이 가설이 참이라면 두 가지가 따라온다.**

**(a) "전략적 멀티클라우드"라는 방어 논리가 약하다.** 의도적 이중화가 아니라 경로의존이라면, 비용 논리로 흔들 여지가 있다. 관측되는 비효율:
- AWS → GCP Outbound Data Transfer **월 $130K+** (Account Plan v2.0 기재)
- 연환산: $130K × 12 × 1,400 = **21.84억 원**
- 이는 **어떤 기능도 만들지 않는 순수 이동 비용**이다

**(b) 그러나 전환비용이 이미 매우 크다.** BigQuery에 강결합된 자산 목록:
컬럼 리니지, 이벤트센터, KarrotMetrics, 실험 플랫폼, **data-mcp**(BigQuery·실험·로그·리니지·Superset 전부를 MCP 서버로 구성), 203개 ELT 파이프라인, sqlglot 기반 SQL 파싱 거버넌스.

> **정리 3 (Theorem 3).**
> DW 이전은 **논리적으로 정당하지만 실행 가능성이 낮은** 전형적 케이스다. 비용 논리(연 21.84억 egress + BigQuery 운영비)는 성립하나, 전환비용은 그 배수다.
>
> 따라서 올바른 제안은 **전면 이관이 아니라 스코프 축소**다:
> ```
> ❌ "BigQuery를 걷어내고 새 DW로 전환"
> ✅ "BigQuery는 메인 DW로 유지. AI/ML 워크로드가 소비하는 데이터 레이어만
>     AWS에 근접 배치해 왕복 이동을 줄인다"
> ```
> 후자는 고객이 2026년 과제로 선언한 **"흩어진 시도를 하나의 흐름으로 통합"** 과 정렬되고, 전자는 정면 충돌한다.

**부수 관찰.** 1부문 플랜은 Databricks($1.2M), 2부문·Snowflake 라인은 별도 딜을 진행 중이다(2026.9.8, Snowflake Commercial 엄상렬 이사: *"당근마켓 — 메가존과 sync-up하면서 함께 딜을 진행하고 있다"*). **정리 3이 참이라면 어느 제품이냐는 2차 문제이고, 스코프 정의가 1차 문제다.** 제품 선택으로 부문 간 충돌을 빚는 것은 논점 이탈이다.

### VI-2. 확률 모델

전사 단위 제안이 채택되려면 **n개 조직이 각각 독립적으로 승인**해야 한다. 조직 i의 승인 확률을 p_i라 하면:

```
P(전사 동시 채택) = Π p_i
```

n = 9 (버티컬 5 + 크로스 4)일 때:

| 조직별 승인 확률 p | P(전사 채택) = p⁹ |
|:---:|---:|
| 0.5 | **0.20%** |
| 0.6 | 1.01% |
| 0.7 | 4.04% |
| 0.8 | 13.4% |

**순차 확산 모델**과 비교한다. 첫 조직 랜딩 후 레퍼런스 효과로 후속 조직의 승인 확률이 p → p′ 로 상승한다고 가정하면:

```
P(k개 조직 침투) = p × p′^(k-1)
```

p = 0.5, p′ = 0.8, k = 5 인 경우:

```
0.5 × 0.8⁴ = 0.5 × 0.4096 = 20.5%
```

> **정리 5 (Theorem 5).**
> 동일 가정(p=0.5)에서 **전사 일괄 제안의 성공 확률(0.20%)과 순차 확산의 5개 조직 침투 확률(20.5%)은 약 100배 차이**다.
>
> 따라서 분산 의사결정 조직에서는 **"전사 표준 도입" 제안 자체가 전략적 오류**다. 5월 플랜이 *"Bedrock 전환을 첫 도미노로 활용 → 성공 사례를 전개하여 버티컬 서비스별 침투"* 라고 쓴 것은 이론적으로 정확하다.

## VII. 재무 압박의 전달 경로 — 성장 둔화가 클라우드에 닿는 방식

### VII-1. 성장률 추정

```
2025 연결 매출        = 2,707억 원, YoY +43%
2025 분기 평균        = 2,707 ÷ 4 = 676.8억 원
2026 1Q 실적          = 783.8억 원
∴ 1Q vs 전년 분기평균 = 783.8 ÷ 676.8 = +15.8%
```

계절성 미반영이므로 실제 연간 성장률은 이보다 높을 수 있다. 그러나 **+43% → +16%대라는 방향성은 뒤집히지 않는다.**

### VII-2. 수익성의 이례적 개선

| 지표 | 2025 | 2026 (추정) |
|---|---:|---:|
| 연결 영업이익 | 146억 | **400억** (A5) |
| 연결 영업이익률 | 5.4% | **12.8%** |

> **성장률은 반토막, 이익률은 2.4배.** 이 조합은 **"성장 기업 → 수익 기업"** 전이의 교과서적 패턴이다.

### VII-3. 자회사 구조 — 압박의 진원지

```
자회사 연결 매출 기여  = 2,707 − 2,690 = +17억 원
자회사 연결 이익 훼손  = 146 − 671 = −525억 원

알려진 손실:
  캐롯 캐나다 순손실  = 375억 원
  당근페이 순손실     =  98억 원
  소계               = 473억 원
  미설명 잔차         = 525 − 473 = 약 52억 원 (일본·미국 법인 등 추정)
```

> ⚠️ **회계상 엄밀성 경고.** 영업이익 갭과 순손실은 계정이 다르고 연결조정·내부거래 제거가 섞인다. 위 계산은 **자릿수 파악 전용**이며, 정확한 분해는 감사보고서 확인 후에만 인용한다. `[CONFIRM]`

### VII-4. 압박의 전달 경로

```
성장 둔화 (+43% → +16%)
        ↓
평가 기준이 성장률 → 이익률로 전환
        ↓

### IX-3. 마진 감도 — 갭의 자기모순

MZC 마진율은 비공개이므로 절대금액이 아닌 **감도**로 분석한다.

```
기준 매출 = 506.9억 원 (2025 Run-Rate)
마진 1%p 하락 = 506.9억 × 0.01 = 5.069억 원/년 손실

목표 갭 18.9억 원을 마진으로 환산:
  18.9 ÷ 5.069 = 3.73%p
```

> **정리 7 (Theorem 7) — 갭의 자기모순.**
> **2026 목표 갭 18.9억 원은 리셀 마진 3.73%p와 등가다.**
>
> 따라서 갭을 메우기 위해 신규 물량에 3.73%p를 초과하는 할인을 제공하면, **그 할인이 곧 다음 해의 갭을 재생산한다.** 갭은 할인으로 메울 수 없다.
>
> 그리고 이것이 **우선순위의 근거**다:
> ```
> 경쟁입찰로 500억 전체 마진이 1%p 침식  =  연 5.069억 손실
> 경쟁입찰로 500억 전체 마진이 4%p 침식  =  연 20.3억 손실 > 목표 갭 18.9억
> ```
> **단가 방어가 갭 해소보다 금액적으로 크다.** 하반기 1번 목표는 매출 증대가 아니라 단가 방어여야 한다.
