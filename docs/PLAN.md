## P0-A: Preply 수업 노트 파이프라인 (G1)

### 아키텍처 결정
**2계층 설계 — 시드 스냅숏 + 런타임 동기화.**
- **L1 시드(즉시 가치)**: Notion 실사에서 확보한 1~7회차 커리큘럼을
  `data/preplyNotes.json`으로 스냅숏 → 오늘부터 토큰 설정 없이 수업 노트
  화면·SRS 카드 파이프라인이 동작. 오프라인 폴백의 최종 바닥이기도 하다.
- **L2 런타임 동기화**: `/app/api/notion/preply` 서버 라우트(NOTION_API_KEY +
  NOTION_PREPLY_PAGE_ID 환경변수) → 페이지 트리 순회 → 노트 원문 반환.
  클라이언트 동기화 엔진이 재시도(지수 백오프 2회)·로컬 캐시(va_preply_notes)·
  오프라인 폴백(캐시→시드 순)을 책임진다.
- **왜 서버 파싱이 아니라 클라이언트 AI 구조화인가**: 노트가 자유 서식
  (미팅노트 요약)이라 정규식 파싱은 회차마다 깨진다. 기존 aiGuard 파이프라인
  (한국어 검증+재시도+safeJson)으로 문장/약점/숙제를 추출하고 **노트별 1회
  캐시**(va_preply_extract, 노트 해시 키) — 토큰 비용 O(신규 노트 수).
- **양방향 중 쓰기 방향은 미구현**: 에스컬레이션 경계(Notion 자동 쓰기).
  REPORT에서 사용자 확인 요청. 읽기 전용으로도 "노트→카드" 핵심 가치는 완성.

### 수용 기준 (AC)
1. 토큰 미설정 상태에서도 수업 노트 화면이 시드 7개 회차를 보여준다
   (미설정 안내 + 설정 방법 표시).
2. 노트의 문장이 "SRS에 넣기"로 va_weak(cat '수업')·표현장에 멱등 등록되고,
   등록된 카드가 세션 워밍업 통합 큐에 자연히 흘러든다.
3. 동기화 실패(5xx×2) 후 성공 시 재시도로 회복하고, 전부 실패하면 캐시/시드로
   폴백하며 상태 라벨(마지막 동기화·시드·오프라인)이 정확하다.
4. 회차 문장으로 드릴 핸드오프가 동작한다.
5. 신규 e2e(48-preply)가 위 1~4를 고정한다.

## P0-B: Lighthouse 90+ (G2)
- 프로덕션 빌드에 `npx lighthouse`(모바일 에뮬레이션) 실행 →
  Performance/Accessibility/Best Practices 측정.
- 90 미만 항목은 원인별 수정 후 재측정(목표 각 90+; PWA 카테고리는 참고 기록).
- AC: 3개 카테고리 90+ 또는, 구조적으로 불가한 항목은 원인·근거를 REPORT에 명시.

## P1-A: 튜터 교차 세션 기억 (G3의 무료 부분)
- 회화 종료 시 대화 요약(기존 요약 기능 재사용 불가 시 마지막 N턴)을
  va_tutor_memory에 저장 → 다음 회화 시스템 프롬프트에 "지난 대화 요약 +
  최근 교정 3건" 주입. AC: 새 세션 첫 응답의 시스템 프롬프트에 이전 맥락
  포함(e2e로 프롬프트 페이로드 검증).

## P1-B: 신설 화면 상태 4종 설계 (G4)
