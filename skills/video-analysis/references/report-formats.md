# 리포트 포맷

용도가 특정되지 않으면 §1 타임라인 리포트를 쓴다. 사용자가 용도를 밝히면
해당 절의 변형으로 간다. 어떤 포맷이든 **모든 주장에 `[mm:ss]`를 붙인다.**

## 1. 타임라인 리포트 (기본)

```markdown
## 한 줄 요약
[이 영상이 무엇이고 무엇을 위한 것인지 한 문장]

## 기본 정보
- 길이 12:30 · 1920x1080 · 음성 있음(한국어) · 샘플 32프레임 / 시트 2장

## 타임라인
| 구간 | 화면 | 발화 |
|---|---|---|
| 00:00–01:12 | [보이는 것] | [말한 것 요약] |
| 01:12–04:30 | ... | ... |

## 핵심 포인트
- [발견 1] — [02:14]
- [발견 2] — [07:41]

## 주의 / 불확실
- [추정] 표시 항목
- 판독 불가 구간, 전사 신뢰도 낮은 지점
```

구간은 장면 전환을 따른다(`index.json`의 scene 타임코드가 그대로 구간 경계다).
"화면"과 "발화"를 분리하는 게 핵심이다 — 둘이 어긋나는 지점이 대개 가장 중요한
정보다(말은 A라는데 화면은 B).

## 2. 요약 브리프 — "그래서 뭔데?"

사용자가 빠른 파악만 원할 때. 타임라인 표를 빼고 결론만 남긴다.

```markdown
## 결론
[3문장 이내]

## 근거
1. [주장] — [mm:ss]
2. [주장] — [mm:ss]
3. [주장] — [mm:ss]

## 놓치면 안 되는 것
- [한 줄]
```

## 3. 장면 인덱스 — 되찾아보기 위한 목차

긴 강의·세미나·아카이브 영상. 사람이 원하는 지점으로 점프하게 만드는 게 목적이다.

```markdown
| 시각 | 챕터 | 내용 |
|---|---|---|
| 00:00 | 오프닝 | ... |
| 04:12 | [주제 A] | ... |
```

챕터명은 짧게. 검색어로 쓰일 단어를 넣는다.

## 4. 데모 / 제품 영상 리뷰

```markdown
## 데모 흐름
1. [단계] — [mm:ss]

## 확인된 기능
| 기능 | 근거 | 비고 |
|---|---|---|

## 화면에서 읽은 텍스트
- [mm:ss] "[UI에 실제로 보인 문자열]"

## 확인 불가
- [샘플 프레임에서 보이지 않은 것]
```

화면 텍스트는 **보이는 그대로** 옮긴다. 해상도가 낮아 확신이 없으면 그렇게 적고,
`--width 960`으로 해당 구간을 재추출한다.

## 5. QA / 버그 리포트

화면 녹화로 재현 절차를 잡을 때.

```markdown
## 재현 절차
1. [00:03] [행동]
2. [00:11] [행동]

## 관찰된 이상
- [mm:ss] [증상] — [화면 근거]

## 기대 동작 vs 실제
| 시각 | 기대 | 실제 |
|---|---|---|

## 환경 단서
- [화면에서 확인된 OS/브라우저/버전 등, 없으면 "확인 불가"]
```

## 6. 미팅 / 통화 녹화

세일즈 맥락이면 이 스킬에서 멈추지 말고 `sales-hunter-ops`의 출력 규칙과
`sfdc-activity-hub`의 활동 로그 포맷으로 넘긴다. 이 스킬이 만드는 것은 **원재료**다:

```markdown
## 참석자 (화면·문맥 근거)
- [이름/역할] — 근거 [mm:ss]  ※ 확신 없으면 [추정]

## 논의 흐름
| 구간 | 주제 | 요지 |

## 결정된 것
- [결정] — [mm:ss]

## 액션 아이템
| 담당 | 내용 | 기한 | 근거 |

## 미해결 / 확인 필요
- [항목] — [mm:ss]
```

숫자·금액·고객사명은 전사 오류가 잦다. 반드시 `[확인 필요]`를 달거나 프레임으로
교차 검증한다. 잘못 옮긴 숫자 하나가 딜을 흔든다.

## 7. 공통 금지

- 프레임에도 전사문에도 없는 내용을 쓰지 않는다.
- "아마", "~인 것 같다"를 근거 없이 쓰지 않는다. 추정이면 `[추정]`으로 명시한다.
- 샘플에 안 잡혔다고 "없다"고 단정하지 않는다 — "샘플 범위에서 미확인"이다.
- 화면에 보인 개인정보·인증정보는 원문 전재 금지. 위치만 기록하고 알린다.
