# Video Analysis (v1.0)

영상을 **프레임 + 전사문 + 타임라인**으로 환원해 판독하는 범용 엔진.

**전제부터 명확히.** 당신은 영상 파일을 직접 재생할 수 없다. 볼 수 있는 것은 이미지와
텍스트뿐이다. 그래서 이 스킬은 영상을 두 갈래로 분해한다 — 대표 프레임을 묶은
**컨택트 시트(이미지)**, 그리고 시각별로 끊긴 **전사문(텍스트)**. 두 갈래를 같은
타임코드 축에 올려놓는 순간, "몇 분에 무엇이 보이고 무슨 말을 했는가"를 답할 수 있다.

## 1. 파이프라인

작업 디렉터리를 하나 잡고(`<work>` = 임시 폴더 권장) 순서대로 실행한다.
`<skill>`은 이 SKILL.md가 있는 디렉터리.

```bash
# 0. 환경 확인 — 한 번만. ffmpeg이 없으면 여기서 설치 안내가 나온다
bash <skill>/scripts/preflight.sh

# 1. 메타데이터 + 샘플링 계획. 항상 먼저 실행해 규모를 파악한다
python3 <skill>/scripts/probe.py "<video>"

# 2. 키프레임 -> 컨택트 시트 (계획이 준 값을 그대로 넣는다)
python3 <skill>/scripts/keyframes.py "<video>" --outdir <work>/frames \
        --max-frames 32 --grid 4x4

# 3. 오디오 추출 + 분할 (무음 영상이면 exit 2 -> 건너뛴다)
python3 <skill>/scripts/audio.py "<video>" --outdir <work>/audio

# 4. 전사 (한국어면 --language ko, 고유명사는 --prompt로 힌트를 준다)
python3 <skill>/scripts/transcribe.py <work>/audio --language ko
```

그다음 **판독**한다:

1. `<work>/frames/index.json`을 먼저 읽는다 — 어느 셀이 몇 분인지 알아야 시트가 의미를 갖는다.
2. `<work>/frames/sheet_*.jpg`를 **한 장씩** 이미지로 읽는다.
3. `<work>/audio/transcript.md`를 읽는다 — `[mm:ss] 발화` 한 줄 포맷이다.
4. 둘을 타임코드로 병합해 리포트를 쓴다 (§4).

## 2. 스크립트 계약

| 스크립트 | 하는 일 | 핵심 산출물 |
|---|---|---|
| `preflight.sh` | ffmpeg/ffprobe/drawtext/STT 백엔드 점검 | 설치 안내, exit 1이면 진행 불가 |
| `probe.py` | 길이·해상도·오디오 유무 + 샘플링 계획 | 화면 출력 (`--json`도 가능) |
| `keyframes.py` | 장면 전환 감지 → 프레임 추출 → 시트 타일링 | `sheet_NN.jpg`, `index.json` |
| `audio.py` | 16kHz 모노 추출, 25MB 한도로 분할 | `audio.mp3` 또는 `chunks/`, `audio_index.json` |
| `transcribe.py` | Groq/OpenAI/로컬 whisper 전사 + 오프셋 병합 | `transcript.md` / `.json` / `.srt` |

전체 옵션과 튜닝은 `references/pipeline.md`.
STT 백엔드·API 키·한국어 처리는 `references/transcription.md`.

## 3. 컨택트 시트 읽는 법

시트는 **좌→우, 위→아래** 순으로 시간이 흐른다. `index.json`의 `cells` 배열이
`R1C1 = 00:00` 식으로 셀 좌표와 타임코드를 짝지어 준다.

- `labels_burned_in: true`면 프레임 좌상단에 타임코드가 찍혀 있다. 그대로 읽으면 된다.
- `false`면(정적 ffmpeg 빌드는 drawtext가 없는 경우가 많다) **반드시 index.json으로
  좌표를 환산한다.** 눈대중으로 시간을 추정하지 않는다.
- 시트 안 검은 빈 칸은 패딩이다. 내용이 아니다.

**중요한 한계 하나.** 프레임은 표본이다. 프레임에 없는 것을 "없었다"고 단정하지 않는다.
"샘플된 32프레임 범위에서는 보이지 않음"이라고 쓴다.

## 4. 출력 — 기본은 타임라인 리포트

용도를 특정하지 않은 요청이면 이 형태로 답한다. 전체 템플릿과 용도별 변형(요약
브리프 / 장면 인덱스 / QA 시트)은 `references/report-formats.md`.

```markdown
## 한 줄 요약
[영상이 무엇인지, 무엇을 위한 것인지 한 문장]

## 기본 정보
길이 · 해상도 · 음성 유무 · 언어 · 샘플 프레임 수

## 타임라인
| 구간 | 화면 | 발화 |
|---|---|---|
| 00:00–01:12 | [보이는 것] | [말한 것 요약] |

## 핵심 포인트
- [발견] — 근거 [mm:ss]

## 주의/불확실
- [추정] 표시가 붙은 항목, 판독 불가 구간
```

**타임코드 인용은 의무다.** 모든 주장에 `[mm:ss]`를 붙인다. 근거 시각을 못 대는
문장은 리포트에서 뺀다.

## 5. 판독 가드레일

1. **본 것만 쓴다.** 프레임에 없고 전사문에도 없는 내용은 쓰지 않는다. 맥락상
   그럴듯한 추론은 `[추정]`을 붙여 분리한다.
2. **STT는 틀린다.** 고유명사·숫자·금액은 특히 그렇다. 중요한 숫자는 `[전사 확인 필요]`로
   표시하고, 가능하면 해당 시각의 프레임을 다시 봐서 화면 텍스트로 교차 검증한다.
3. **화자를 지어내지 않는다.** Whisper는 화자 분리를 하지 않는다. 화면·문맥으로
   구분이 되면 그 근거를 밝히고, 안 되면 화자 표기를 생략한다.
4. **개인정보.** 화면에 계정·연락처·고객 실명·API 키가 보이면 리포트에 원문으로
   옮기지 말고 "민감정보 노출 [mm:ss]"로만 기록하고 사용자에게 알린다.
5. **원본을 건드리지 않는다.** 모든 산출물은 `<work>` 아래에만 쓴다.

## 6. 토큰 예산 — 길이별 전략

컨택트 시트 한 장은 대략 1,600 토큰이다. 전사문은 1시간에 8~10k 토큰.

| 길이 | 프레임 | 접근 |
|---|---|---|
| ~2분 | 16 (4x4 한 장) | 전체 판독 |
| 2~15분 | 32 (두 장) | 전체 판독 |
| 15~60분 | 48 (세 장) | 전사문 먼저 읽고 관심 구간만 프레임 재추출 |
| 60분+ | 64 상한 | **구간을 나눈다.** `--start/--end`로 창을 잘라 반복 |

긴 영상에서 특정 구간이 중요해지면 그 구간만 다시 촘촘히 뽑는다:

```bash
python3 <skill>/scripts/keyframes.py "<video>" --outdir <work>/zoom \
        --start 1520 --end 1700 --mode interval --interval 3 --grid 3x3
```

## 7. 자주 만나는 상황

- **무음 영상** — `audio.py`가 exit 2로 끝난다. 프레임만으로 판독하고, 리포트에
  "음성 없음"을 명시한다.
- **화면 녹화(데모·튜토리얼)** — 장면 전환이 약해 scene 감지가 잘 안 걸린다.
  `--mode interval --interval 10` 쪽이 낫다. UI 텍스트를 읽어야 하므로 `--width 960`으로
  해상도를 올린다.
- **세로 영상(쇼츠)** — `--grid 6x2`처럼 가로로 긴 배치가 시트를 덜 낭비한다.
- **자막 트랙이 이미 있는 파일** — STT보다 정확하다. 먼저 뽑아 본다:
  `ffmpeg -i "<video>" -map 0:s:0 <work>/subs.srt` (없으면 실패하니 그때 STT로 간다.)
- **URL만 있고 파일이 없음** — 이 스킬은 로컬 파일만 다룬다. 사용자에게 파일을
  받거나, 사용자가 직접 `yt-dlp`로 받도록 안내한다. 임의로 다운로드하지 않는다.
- **ffmpeg이 없고 설치 권한도 없음** — `pip install imageio-ffmpeg` 한 줄이면
  정적 바이너리가 딸려 오고 `ffkit`이 자동으로 찾는다.
